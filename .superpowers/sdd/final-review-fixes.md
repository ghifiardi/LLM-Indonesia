Security fix: static file handler in tantular_office_addin/tools/dev-server.mjs served every file under the served root (including data/workspace.json and certs/localhost.key) with Access-Control-Allow-Origin: * — any web page could fetch the workspace store or TLS private key, bypassing the /api/workspace origin allowlist. Fix: hard-block requests whose resolved path's first segment is data/ or certs/, returning 404 (not 403, to avoid confirming existence), applied before any fs.readFile — existing path-traversal check (filePath.startsWith(root)) left intact. Added tantular_office_addin/.gitignore (data/, certs/) — neither directory was previously tracked in git (git ls-files data/ and git ls-files certs/ both empty), so nothing needed untracking. New test tests/devServerStatic.test.mjs spawns the real dev-server.mjs as a child process on a free port and verifies: GET /data/workspace.json -> 404, GET /certs/localhost.key -> 404, a path-traversal-flavored /./data/workspace.json -> 404, GET /src/taskpane.html -> 200 (normal static asset unaffected), GET /api/workspace with no Origin header -> 200 (API allowlist behavior unchanged). 155 tests total, 155 pass, 0 fail (154 pre-existing + 1 new test file covering the above 5 assertions).

Follow-up security fix (case-insensitive filesystem bypass): reviewer demonstrated that the data/certs block above used a case-sensitive `===` comparison (`relativeSegments[0] === "data"`), which is bypassable on case-insensitive filesystems — macOS APFS and Windows NTFS resolve `GET /DATA/workspace.json` and `GET /Certs/localhost.key` to the same files as their lowercase paths, so `fs.readFile` served them with 200 while the guard's strict string compare missed the uppercase/mixed-case variants. Fix (tantular_office_addin/tools/dev-server.mjs, ~line 95-105): lowercase the first path segment before comparing (`const firstSegment = relativeSegments[0]?.toLowerCase(); if (firstSegment === "data" || firstSegment === "certs") { ...404... }`), with a comment noting this intentionally over-blocks on case-sensitive Linux filesystems (e.g. a real top-level `Data/` or `CERTS/` folder would now also 404), which is acceptable and safer than under-blocking. Extended tests/devServerStatic.test.mjs (same spawned-server test) with three more assertions: GET /DATA/workspace.json -> 404, GET /Certs/localhost.key -> 404, GET /dAtA/workspace.json -> 404. Verified regression: reverting the fix to the pre-fix `===` line and running `node --test tests/devServerStatic.test.mjs` fails with `200 !== 404` on the /DATA/workspace.json case; re-applying the fix passes. Full suite: 155 tests total (test count unchanged since assertions were added to the existing test block rather than a new one), 155 pass, 0 fail.
